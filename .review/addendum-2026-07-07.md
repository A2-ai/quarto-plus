## REVIEW ADDENDUM (survey pass, 2026-07-07)

### CONTEXT

- Codebase: quarto-plus — a Quarto extension (pandoc Lua filters + shortcodes)
  adding Microsoft Word/OOXML features to docx rendering: Word TOC /
  list-of-figures / list-of-tables fields, an `abbreviations.tex`-driven
  glossary with `\gls`-family expansion, bookmark-based figure/table captions
  with cross-references, header formatting compliance, and an inline
  Word-style shortcode.
- Primary consumers: internal pharmacometrics/clinical report authors
  rendering client-facing Word reports via the `A2-ai/quarto-report` template
  (inferred from README and PK/PD sample glossary) (?).
- Known constraints or intentional decisions worth flagging up front: docx is
  the only output target for now; PDF is a plausible future target [Q5].
  Naive `"s"` pluralization of glossary terms is an accepted limitation [Q6].
  Renders must never fail because of a shortcode/author error — fail-soft is
  policy [Q3]. Absence of tests/CI is a deliberate choice given the
  complexity of Quarto setup and render [Q8].
- Areas of specific concern: silent failure modes that put wrong, stale, or
  placeholder content into delivered Word documents; behavior in Quarto book
  projects, which are in scope alongside single-file `.qmd` renders [Q7].

### PRIORITY TARGETS

Roughly 80% of review effort here, in this order.

1. **Cross-reference architecture: dual numbering authorities + document-order
   coupling (H2).** Forward references are a supported authoring pattern and
   must work as well as achievable [Q2 — maintainer answer]. In
   `_extensions/quarto-plus/crossref.lua`: caption display
   numbers come from live Word `SEQ` fields but crossref cached text comes
   from Lua encounter-order counters (`:22-24,75-77`); forward references
   resolve to `"??"` (`:140-143`); the `REF` field omits `w:dirty="true"`
   (`:146-148`) unlike every other field in the codebase (compare `:41`,
   `table_of_contents.lua:46`); unknown-prefix bookmark IDs fall through to
   label `"Unknown"` while still emitting a `REF` (`:128-137`). Trace both
   caption shortcodes and `crossref` end-to-end; test a forward reference and
   a non-matching bookmark ID; inspect the rendered `document.xml`. A
   truly-missing caption is acknowledged as unrecoverable [Q2]; the review
   target is references whose captions exist but resolve stale or not at all.

2. **Consistency and visibility of the fail-soft policy (H4, reframed).**
   Not failing the render on shortcode/author errors is intentional policy
   [Q3 — maintainer answer], so do not propose abort-on-error for shortcodes.
   Review instead whether the fail-soft responses are consistent and
   *surfaced*: placeholder prose is injected with no `quarto.log.warning`
   (`_extensions/quarto-plus/style.lua:7`,
   `_extensions/quarto-plus/crossref.lua:15,68`) while unresolved crossrefs
   do warn; and one path violates the stated policy outright — failure to
   write the *unmatched-terms log* hard-aborts the render with a dead warning
   preceding the `error()`
   (`_extensions/quarto-plus/terms_and_abbreviations.lua:32-34`) [Q4 —
   maintainer undecided; default: treat the abort as accidental]. Table every
   author-error path across the five modules and its behavior
   (inject / warn / log-to-file / abort) against the [Q3] policy.

3. **Four-way duplication of `\gls` expansion with observable drift (H3).**
   `_extensions/quarto-plus/terms_and_abbreviations.lua:83-158`: branches at
   `:86,104,121,138` re-implement expand-on-first-use with copy-paste
   variations; log messages already disagree with inserted text (`:110` vs
   `:112`; `:144-145` vs `:147-148`). Diff the four branches, enumerate
   behavioral differences vs. documented intent (`README.md:77-85`), sketch a
   single parameterized expansion function. [Q6]

4. **Quarto book-project behavior (H5, promoted).** Book projects are in
   scope alongside single-file `.qmd` [Q7 — maintainer answer], and nothing
   in the code or docs addresses them. Verify: (a) module-local state in the
   shortcode and filter files — `crossref.lua`'s counters and id maps
   (`:5-9`), `terms_and_abbreviations.lua`'s `seenAcronyms`/`unmatchedTerms`
   (`:62-65`) — behaves correctly across chapters in a docx book render (is
   it one pandoc invocation or per-chapter state resets? do bookmark IDs
   collide across chapters?); (b) relative-path resolution of
   `abbreviations-file` and the unmatched log when rendering from project
   root vs. a chapter subdirectory
   (`terms_and_abbreviations.lua:2-3,9,24`; commit `04a96f0` suggests prior
   breakage); (c) whether per-chapter `Meta` passes pick up config from
   `_quarto.yml` vs. document frontmatter consistently.

5. **Untrusted-input handling at the OOXML boundary (H6 + H8).** Bookmark IDs
   are whitespace-stripped but never validated against Word's bookmark-name
   grammar (`_extensions/quarto-plus/crossref.lua:14,67,120`) — invalid names
   break references only inside Word. TOC style-map values are interpolated
   into the field instruction with no escaping at all
   (`_extensions/quarto-plus/table_of_contents.lua:23-31`, compare `utils.escape_xml`
   usage elsewhere), and supplying a style map silently drops the `\u` switch
   (`:8-13`). Verify Word's grammar for bookmark names and TOC `\t` switches;
   test hostile-ish inputs (commas, quotes, leading digits).

### OPEN HUNT

The ~20% unanchored sweep should favor what this survey did *not* do:

- **No render was performed.** Everything above is from reading source. If
  you can render `example.qmd` (or dry-run pandoc), do it and inspect the
  produced `document.xml` — actual output is the survey's biggest blind spot.
- **OOXML literal validity** in all four emitting files was never
  schema-checked (namespace declarations are present on some roots and absent
  on others — e.g., `crossref.lua:146` declares `xmlns:w`, `style.lua:14` does
  not).
- **`header.lua`** got the least attention: whether a literal tab inside
  `pandoc.Str` survives the docx writer as a real tab character, and the
  seemingly-dead empty-string condition at `:16`.
- **Meta-value handling** across all filters: `pandoc.utils.stringify` on
  booleans/lists, `indent-headers` string comparison (`header.lua:7`),
  malformed `toc-style-map` entries (missing `style` or `level` keys).
  (Relative-path resolution moved to priority target 4.)

### KNOWN-INTENTIONAL / OUT OF SCOPE

- Dot-prefixed div classes: matching `::: .toc` with the class stored
  *including* the literal dot is intentional, following Quarto's own div
  conventions such as `.landscape` [Q1 — maintainer answer]. Do not flag the
  div-class contract or non-support of the braced `::: {.toc}` form as a
  finding.
- Fail-soft on shortcode/author errors is policy: a shortcode failure must
  never fail the render [Q3 — maintainer answer]. Do not propose
  abort-on-error for shortcodes; the *consistency and visibility* of the
  fail-soft responses remains in scope (see priority target 2).
- Absence of automated tests/CI is a deliberate maintainer choice given the
  complexity of Quarto setup and render; some external repos use the
  extension but carry no validation either [Q8 — maintainer answer]. Do not
  report the testing gap as a finding.
- Removing empty level-1 headers and tab-indenting the rest is deliberate
  product behavior for Word formatting compliance (source: `README.md:17-21`);
  review the implementation, not the behavior.
- The `"??"` fallback string for unresolved crossrefs was deliberately chosen
  over `nil` (source: commit `047045e` "nil -> ??"). The *string choice* is
  intentional; the staleness/forward-reference mechanics around it are in
  scope (see priority target 1).
- docx-only output focus for now [Q5 — maintainer answer; PDF is a possible
  future target]: do not flag that raw OOXML blocks are meaningless in
  HTML/PDF output.
- Naive `"s"` pluralization rule [Q6 — maintainer answer: accepted]: the
  linguistic rule itself is accepted; the code duplication around it is in
  scope.
- `.review/` contents (this workflow's own files) are not part of the
  reviewed system.

### REPO MAP

**Purpose.** `quarto-plus` is a Quarto extension (Lua filters + shortcodes)
that adds Microsoft Word/OOXML-specific features to `docx` rendering: native
Word TOC / list-of-figures / list-of-tables fields, a glossary/abbreviations
system driven by a LaTeX-style `abbreviations.tex`, bookmark-based figure/table
captions with cross-references, header formatting compliance, and an inline
Word-style shortcode. Codebase type: **plugin/library** (pandoc Lua filters —
no main, no service). Consumers appear to be pharmacometrics/clinical report
templates (PK/PD sample glossary, README references an `A2-ai/quarto-report`
template) `(?)`.

**Entry points** — all registered in
`_extensions/quarto-plus/_extension.yml` (version 0.2.0, requires Quarto
>= 1.6.36):

- Shortcodes (run before filters, during parse): `style.lua` (`{{< style >}}`),
  `crossref.lua` (`{{< tbl_caption >}}`, `{{< fig_caption >}}`,
  `{{< crossref >}}`).
- Filters (run in listed order): `header.lua`, `table_of_contents.lua`,
  `terms_and_abbreviations.lua`.

**Module inventory** (all under `_extensions/quarto-plus/`):

| File | Lines | Responsibility | Notable deps / state |
|---|---|---|---|
| `terms_and_abbreviations.lua` | 197 | Parse `\newacronym` entries from a `.tex` file (Meta pass); expand `\gls`/`\glspl`/`\Gls`/`\Glspl` RawInlines with first-use definition; render `.abbreviations` div as a sorted table; write unmatched-terms log (Pandoc pass) | `io.open` (reads `abbreviations.tex`, writes log file); module-local `acronymTable`, `seenAcronyms`, `unmatchedTerms`; meta keys `abbreviations-file`, `unmatched-glossary-log` |

Root-level: `README.md` (user docs), `example.qmd` (the only test artifact —
a manual render exercising every feature), `abbreviations.tex` (sample glossary
with PK/PD entries), `LICENSE`, `.review/` (this workflow).

**Layering.** Flat by design — five independent filter/shortcode modules
sharing only `utils.lua`. The only cross-module contract is implicit:
`crossref.lua`'s caption shortcodes and `table_of_contents.lua`'s
list-of-figures/tables fields must agree on the Word `SEQ` identifiers
`Figure`/`Table` (they do, by string convention in two files).

**Most load-bearing:** `crossref.lua` and `terms_and_abbreviations.lua`
(nearly all state and logic); `utils.lua` (highest fan-in, required by both
shortcode files).

**Cross-cutting concerns:**

- Errors: no single strategy. Mix of fail-soft placeholder text baked into
  output (`crossref.lua:15`, `crossref.lua:68`, `style.lua:7`,
  `crossref.lua:135` `"??"`/`"Unknown"`), `quarto.log.warning` and continue
  (most paths), and one hard `error()` that aborts the render if the
  unmatched-terms *log file* can't be written
  (`terms_and_abbreviations.lua:33`).
- Config: each filter reads its own meta keys in its own `Meta` pass, with
  file-local defaults at the top of each file. No shared config point, but
  keys don't overlap.
- Logging: pervasive `quarto.log.debug`, warnings for user-visible problems.
- Concurrency/auth: none (single-threaded pandoc traversal).
- State lifecycle: module-local upvalues, reset per render process `(?)` — in
  multi-file Quarto projects (books), whether shortcode state persists across
  input files was not verified.

**Build/test/CI:** none of the three. No `.github/`, no test files, no lint
config committed (`.luarc.json` is gitignored — local LSP only). The de facto
test is manually rendering `example.qmd` to docx and eyeballing the result.
Git history shows small PR-based iterations (#1–#7).
