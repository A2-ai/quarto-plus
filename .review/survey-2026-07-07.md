# Survey — quarto-plus (2026-07-07)

Pass 1 of the two-pass architecture review. This document produces targeting,
not findings. Companion file: `.review/addendum-2026-07-07.md`.

## 1. Repository map

**Purpose.** `quarto-plus` is a Quarto extension (Lua filters + shortcodes)
that adds Microsoft Word/OOXML-specific features to `docx` rendering: native
Word TOC / list-of-figures / list-of-tables fields, a glossary/abbreviations
system driven by a LaTeX-style `abbreviations.tex`, bookmark-based figure/table
captions with cross-references, header formatting compliance, and an inline
Word-style shortcode. Codebase type: **plugin/library** (pandoc Lua filters —
no main, no service). Consumers appear to be pharmacometrics/clinical report
templates (PK/PD sample glossary, README references an `A2-ai/quarto-report`
template) `(?)`.

**Entry points** — all registered in
`_extensions/quarto-plus/_extension.yml` (version 0.2.0, requires Quarto
>= 1.6.36):

- Shortcodes (run before filters, during parse): `style.lua` (`{{< style >}}`),
  `crossref.lua` (`{{< tbl_caption >}}`, `{{< fig_caption >}}`,
  `{{< crossref >}}`).
- Filters (run in listed order): `header.lua`, `table_of_contents.lua`,
  `terms_and_abbreviations.lua`.

**Module inventory** (all under `_extensions/quarto-plus/`):

| File | Lines | Responsibility | Notable deps / state |
|---|---|---|---|
| `terms_and_abbreviations.lua` | 197 | Parse `\newacronym` entries from a `.tex` file (Meta pass); expand `\gls`/`\glspl`/`\Gls`/`\Glspl` RawInlines with first-use definition; render `.abbreviations` div as a sorted table; write unmatched-terms log (Pandoc pass) | `io.open` (reads `abbreviations.tex`, writes log file); module-local `acronymTable`, `seenAcronyms`, `unmatchedTerms`; meta keys `abbreviations-file`, `unmatched-glossary-log` |
| `crossref.lua` | 164 | Three shortcodes emitting raw OOXML: captions create bookmarks + Word `SEQ` fields and record IDs in Lua maps; `crossref` emits a `REF` field with a cached "Label N" resolved from those maps | `require("utils")`; module-local `figure_id_map`, `table_id_map`, three counters; meta keys `caption-style-figure`, `caption-style-table` |
| `table_of_contents.lua` | 128 | Replace divs classed `.toc` / `.list_of_figures` / `.list_of_tables` with raw OOXML `TOC` field blocks | meta keys `toc-levels`, `toc-style-map` |
| `header.lua` | 45 | Remove empty level-1 headers; prepend a tab `Str` to remaining headers | meta key `indent-headers` |
| `style.lua` | 25 | `{{< style >}}` shortcode → OOXML paragraph with a `pStyle` | `require("utils")` |
| `utils.lua` | 8 | `escape_xml` (escapes `& < > "`) | — |

Root-level: `README.md` (user docs), `example.qmd` (the only test artifact —
a manual render exercising every feature), `abbreviations.tex` (sample glossary
with PK/PD entries), `LICENSE`, `.review/` (this workflow).

**Layering.** Flat by design — five independent filter/shortcode modules
sharing only `utils.lua`. The only cross-module contract is implicit:
`crossref.lua`'s caption shortcodes and `table_of_contents.lua`'s
list-of-figures/tables fields must agree on the Word `SEQ` identifiers
`Figure`/`Table` (they do, by string convention in two files).

**Most load-bearing:** `crossref.lua` and `terms_and_abbreviations.lua`
(nearly all state and logic); `utils.lua` (highest fan-in, required by both
shortcode files).

**Cross-cutting concerns:**

- Errors: no single strategy. Mix of fail-soft placeholder text baked into
  output (`crossref.lua:15`, `crossref.lua:68`, `style.lua:7`,
  `crossref.lua:135` `"??"`/`"Unknown"`), `quarto.log.warning` and continue
  (most paths), and one hard `error()` that aborts the render if the
  unmatched-terms *log file* can't be written
  (`terms_and_abbreviations.lua:33`).
- Config: each filter reads its own meta keys in its own `Meta` pass, with
  file-local defaults at the top of each file. No shared config point, but
  keys don't overlap.
- Logging: pervasive `quarto.log.debug`, warnings for user-visible problems.
- Concurrency/auth: none (single-threaded pandoc traversal).
- State lifecycle: module-local upvalues, reset per render process `(?)` — in
  multi-file Quarto projects (books), whether shortcode state persists across
  input files was not verified.

**Build/test/CI:** none of the three. No `.github/`, no test files, no lint
config committed (`.luarc.json` is gitignored — local LSP only). The de facto
test is manually rendering `example.qmd` to docx and eyeballing the result.
Git history shows small PR-based iterations (#1–#7).

## 2. Risk hypotheses (ranked, max 8)

**H1 — The div-class contract silently rejects standard Quarto syntax.**
- **Hypothesis:** All div matching checks for class names *including a literal
  leading dot* (`div.classes:includes(".abbreviations")`,
  `el.classes:includes(".toc")` etc.), which only matches pandoc's
  single-unbraced-word form `::: .toc`; the standard braced form `::: {.toc}`
  produces class `toc` (no dot) and silently no-ops.
- **Signal:** `table_of_contents.lua:39,65,91`;
  `terms_and_abbreviations.lua:164`; README and `example.qmd` exclusively use
  the unbraced form, suggesting the dot-form is load-bearing convention, not
  choice.
- **If true, cost:** A user writing idiomatic Quarto gets a document with no
  TOC/abbreviations table and no warning — a silent content omission in
  deliverable documents.
- **Investigation sketch:** Render a doc with both `::: .toc` and
  `::: {.toc}`; inspect `div.classes` for each (one-line debug filter or
  `pandoc -t native`). Check whether matching both spellings (or normalizing)
  is the fix.
- **Confidence:** high.

**H2 — The cross-reference system is two parallel numbering authorities that
can drift, coupled by document order.**
- **Hypothesis:** Caption *display* numbers come from live Word `SEQ` fields,
  but `crossref` cached text comes from Lua counters incremented in shortcode
  encounter order (`crossref.lua:22-24,75-77`); the two agree only if (a)
  every caption is created via these shortcodes, (b) nothing is reordered in
  Word afterward, and (c) every `crossref` appears *after* its caption
  (forward references yield `"??"`, `crossref.lua:140-143`). Additionally the
  `REF` field is emitted without `w:dirty="true"` (`crossref.lua:146-148`),
  unlike every other field in the codebase, so Word does not refresh the
  stale cached text on open.
- **Signal:** `crossref.lua:41` and `table_of_contents.lua:46` use
  `w:dirty="true"`; `crossref.lua:147` does not. Type detection is by
  bookmark-ID prefix regex (`crossref.lua:128-137`), falling through to
  label `"Unknown"` while still emitting a `REF` field.
- **If true, cost:** Forward references and post-render edits produce wrong
  or `"?? "` cross-references in delivered Word documents; the failure is
  cosmetic-looking but is a correctness defect in regulated reports.
- **Investigation sketch:** Trace both caption shortcodes and `crossref`
  end-to-end; render `example.qmd` variants with a forward reference and a
  non-matching bookmark ID; open the docx XML and check field
  behavior/`dirty` semantics; assess whether cached text should be the SEQ
  value at all.
- **Confidence:** high.

**H3 — Four near-identical `\gls` variant branches have already drifted and
will drift further.**
- **Hypothesis:** `terms_and_abbreviations.lua:83-158` implements the same
  expand-on-first-use policy four times (`\Glspl`, `\glspl`, `\gls`, `\Gls`)
  with copy-paste variations; the copies already disagree with their own log
  messages (e.g., `:110` logs a lowercased expansion but `:112` inserts it
  unchanged; `:144-145` logs a lowercased remainder but `:147-148` inserts
  the original case), and capitalization/pluralization policy (naive `"s"`
  append, first-char upper) is duplicated rather than factored.
- **Signal:** the four branches at `terms_and_abbreviations.lua:86,104,121,138`
  differ only in 1–2 transformation lines each; log/behavior mismatches cited
  above.
- **If true, cost:** Any policy change (pluralization rules, first-use
  formatting, unmatched handling) needs four synchronized edits with no
  mechanism enforcing consistency; drift shows up as wrong casing/plurals in
  documents.
- **Investigation sketch:** Diff the four branches line by line; enumerate the
  actual behavioral differences vs. the intended ones (README documents
  intent at `README.md:77-85`); sketch a single
  `expand(term, {capitalize, pluralize})` factoring.
- **Confidence:** high (duplication is certain; the question is how much
  observable drift).

**H4 — Failure-mode policy is inconsistent, and every inconsistency lands in
the delivered document.**
- **Hypothesis:** There is no coherent policy for "author made a mistake":
  missing shortcode args silently inject placeholder prose into the document
  (`style.lua:7`, `crossref.lua:15,68`), unresolvable crossrefs inject
  `"?? "`, unmatched glossary terms warn + log to a side file, but a mere
  failure to *write that log file* hard-aborts the render
  (`terms_and_abbreviations.lua:32-34` — warning immediately followed by
  `error()`). The severity of the response is roughly inverted relative to
  the severity of the problem.
- **Signal:** the four cited locations; also the log-then-error pattern at
  `terms_and_abbreviations.lua:32-34` where the `error()` makes the preceding
  warning unreachable as a "soft" path.
- **If true, cost:** Placeholder text ("If you see this, you did not provide
  caption text.") shipping inside client-facing regulated documents; renders
  failing for the least important reason in the file.
- **Investigation sketch:** Table every author-error path across the five
  modules × its current behavior (inject / warn / log / abort); propose one
  policy (probably: fail render loudly on missing required args, warn on
  unresolved refs) and identify which behaviors maintainers consider
  intentional [Q4].
- **Confidence:** high.

**H5 — Relative-path resolution for `abbreviations.tex` and the unmatched-log
depends on Quarto's working directory, undocumented and unverified.**
- **Hypothesis:** `io.open(abbrFile, "r")` and the log write
  (`terms_and_abbreviations.lua:9,24`) use paths relative to the process CWD
  at filter-execution time; commit `04a96f0` ("write to quarto project root")
  suggests this bit someone before, and behavior for documents in
  subdirectories, standalone renders (no `_quarto.yml`), or book projects is
  unverified.
- **Signal:** `terms_and_abbreviations.lua:2-3` bare relative defaults;
  README (`README.md:65`) promises "quarto project root" but nothing in code
  resolves against the project root explicitly.
- **If true, cost:** Missing-abbreviations warnings (and thus no expansions)
  or logs written to surprising locations depending on how/where the render
  is invoked.
- **Investigation sketch:** Check Quarto's documented CWD for filters; test
  render from a subdirectory document and a non-project render; consider
  `quarto.project.directory` or env-var based resolution.
- **Confidence:** medium.

**H6 — Word bookmark-name validity is an unvalidated trust boundary.**
- **Hypothesis:** Caption bookmark IDs pass through `gsub("%s+", "")` and XML
  escaping only (`crossref.lua:14,67,120`); Word bookmark names must start
  with a letter and contain only letters/digits/underscores. IDs like
  `"Table 1.2"` or `"1-Figure"` yield bookmarks Word silently drops, so
  matching `REF` fields break in Word with no render-time warning.
- **Signal:** `crossref.lua:14` strips whitespace but validates nothing else;
  README examples happen to use safe values (`"Table 1"` → `Table1`).
- **If true, cost:** Broken cross-references ("Error! Reference source not
  found." after field update) discovered only in the final Word doc.
- **Investigation sketch:** Confirm Word's bookmark-name grammar; grep for
  any validation; test a punctuated bookmark ID end-to-end.
- **Confidence:** medium.

**H7 — Zero automated verification for a system whose failures are silent and
visual.**
- **Hypothesis:** With no tests and no CI, every hypothesis above (and every
  future change) is verified only by hand-rendering `example.qmd`; the OOXML
  strings are never schema-validated, and regressions in field codes would
  ship unnoticed.
- **Signal:** No `.github/`, no test files anywhere; `example.qmd` is the
  only executable artifact; raw OOXML literals in 4 files.
- **If true, cost:** Compounding: each of H1–H6 is exactly the class of bug
  a golden-file docx test (render example.qmd, unzip, assert on document.xml)
  would catch.
- **Investigation sketch:** Assess feasibility of a minimal CI job:
  `quarto render example.qmd`, unzip, grep `document.xml` for expected
  bookmarks/field codes. This is a targeting note for pass 2's operational
  category, not a code trace.
- **Confidence:** high that the gap exists; medium that it's the right spend.

**H8 — `toc-style-map` construction has quoting/semantics edge cases.**
- **Hypothesis:** `table_of_contents.lua:23-31` joins style/level pairs with
  commas into a single `\t "Style,1,Style2,2"` switch; a style name
  containing a comma or quote breaks the field code, and supplying a style
  map drops the `\u` switch entirely (`:8-13`), silently excluding built-in
  heading levels — README (`README.md:38-45`) doesn't say the map *replaces*
  heading-based entries.
- **Signal:** cited lines; no escaping of style names beyond none at all
  (they're interpolated into the field instruction, not XML-escaped either —
  compare `crossref.lua`'s use of `utils.escape_xml`).
- **If true, cost:** Malformed TOC field or user-surprising TOC contents for
  custom-style users.
- **Investigation sketch:** Check Word TOC `\t` switch semantics (does it
  combine with `\o`?); test a style name with a comma; check whether the
  instruction text needs XML escaping.
- **Confidence:** medium.

## 3. Questions for the maintainer (max 10)

**Q1** (→ H1) — Is requiring the unbraced div form `::: .toc` (class stored
*with* the dot) intentional, or should the standard `::: {.toc}` form also
work? **Default:** unintentional; pass 2 treats non-support of the braced
form as a defect.

**Q2** (→ H2) — Are forward cross-references ("see Table 3" before the
caption) a supported authoring pattern? **Default:** supported; the `"??"`
cache + missing `dirty` flag get reviewed as a correctness issue.

**Q3** (→ H4) — When an author omits a required shortcode argument, is
injecting visible placeholder text ("If you see this…") into the rendered
document the intended behavior, versus failing the render? **Default:**
unintentional fail-soft; reviewed as a defect for regulated-document use.

**Q4** (→ H4) — Is aborting the entire render when the *unmatched-terms log*
can't be written (`terms_and_abbreviations.lua:33`) intentional (i.e., the
log is a compliance artifact), or accidental severity inversion? **Default:**
accidental; reviewed as a defect.

**Q5** (→ CONTEXT) — Is docx the only output format this extension will ever
target (no HTML/PDF ambitions)? **Default:** docx-only; pass 2 ignores
other-format behavior of the raw OOXML blocks.

**Q6** (→ H3) — Is naive pluralization (append `"s"` to both the definition
and the abbreviation) an accepted limitation for your glossary domain?
**Default:** accepted; pass 2 reviews the four-way duplication, not the
linguistic rule.

**Q7** (→ H5) — Are multi-file Quarto projects (books/websites) in scope, or
is this strictly single-document reports? **Default:** single-document;
cross-file shortcode-state concerns are noted but not prioritized.

**Q8** (→ H7) — Does any external repo (e.g., `A2-ai/quarto-report`) carry
integration tests that exercise this extension? **Default:** no automated
verification exists anywhere; H7 stands.

  and `TOC` field in the codebase has it; stale cached crossref text on open.

  `error()`s on the same condition; the warning is dead and the abort seems

  expansion; inserted text is not lowercased (same pattern at `:144-148`).
- `header.lua:16` — `el.content[1].text == ""` looks like a dead condition
  (pandoc never emits an empty `Str`), leaving `#el.content == 0` as the only
  live branch.
- `_extensions/.DS_Store` is committed despite `.DS_Store` being in
  `.gitignore` (added before the ignore rule; needs `git rm`).
- `crossref.lua:120` — a `crossref` to an unknown-prefix bookmark emits label
  `"Unknown ??"` *and* a live `REF` field to a possibly-nonexistent bookmark;
